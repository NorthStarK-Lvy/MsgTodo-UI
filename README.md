# MsgTodo-UI

一套 **Android 原生「消息 → 待办」类应用的 UI 框架**，基于
[Jetpack Compose](https://developer.android.com/jetpack/compose) 与
[Miuix](https://github.com/miuix-kotlin/miuix)（HyperOS 设计语言）实现。

> ⚠️ **这不是一个完整的应用。** 本仓库只包含界面层（View），不含任何
> 业务实现：没有通知监听、没有网络请求、没有数据持久化，只有一个
> 内存态的演示壳（`DemoMainActivity`）。拿来直接装，看到的是一套
> 可以点、可以滑、状态会动的空壳界面。

## 这是什么

MsgTodo 的完整形态是一个隐私优先的本地工具：监听手机通知 → 按用户
设定的范围筛选 → 交给用户自己配置的大模型接口判断"要不要变成待办" →
生成待办。本项目开源的是它的**界面层**，包括：

| 模块 | 内容 |
|---|---|
| 待办 | 列表、勾选、编辑、详情（小标题 + 原文）、到期时间染色、提取状态卡 |
| 消息 | 捕获列表、发送判定展示（关注名单 + 安全防线两道闸门的实时结果） |
| 探针 | 各环节计数、失败明细、诊断操作 —— 回答"为什么没反应" |
| 设置 | 大模型配置（文本/视觉双槽位）、隐私、来源、保活、外观（深浅色/悬浮底栏） |
| 组件 | `ContentCard`（按压缩放）、`GroupCard`、大标题折叠、页面转场（按层级判方向） |

## 设计理念

**1. 界面必须诚实。**
界面上每一个"发 / 不发""成功 / 失败"的展示，都直接调用与业务层
同一份判定规则现场计算，而不是缓存一个结论。用户看到的永远是
"如果现在发一条，会发生什么"，不是"曾经发生过什么"。

**2. 状态可视化到"能排障"的粒度。**
"为什么没反应"是这个品类最大的痛点。所以有探针页（每个环节的
计数）、有提取状态卡（在处理谁、已用多久、队列还剩几条）、有失败
明细（哪条、几点、为什么、重试过没有）。原则是：**光给一个数字
不够，要给出下一步往哪查。**

**3. 危险动作降级，安全动作直达。**
删除收进长按 + 确认弹窗；清空类操作永远说明"清的是什么、留的是
什么"；配置状态直接显示在入口摘要上，不让用户点进两级才知道没配。

**4. 视觉规范全部走角色，不写死色值。**
所有颜色通过 `MiuixTheme.colorScheme.*` 角色取色，深浅色切换零
额外代码；首帧底色用资源限定符（`values` / `values-night`）解决，
避免启动闪色。

**5. 注释记录"为什么"，而不是"做了什么"。**
源码里保留了大量决策记录（踩过的坑、被否掉的方案、取舍理由），
希望对同类项目有参考价值。

## 工程结构

```
app/src/main/java/com/msgtodo/
├── ui/      # 全部界面：4 个页签 + 12 个二级/三级页 + 通用组件
├── core/    # 界面依赖的纯逻辑类型（ExtractStatus 等的界面侧形状）
└── data/    # 界面依赖的数据形状（TodoItem / MsgRecord / ApiConfig …）
```

> `core/` 与 `data/` 里只保留**界面需要的类型定义与纯函数**，是主工程
> 对应文件针对 UI 场景的裁剪版，不包含监听、网络、存储等实现。

## 运行演示壳

```bash
./gradlew assembleDebug
```

`DemoMainActivity` 用内存假数据接线了全部页面：可以勾待办、改配置、
切深浅色、开关悬浮底栏、看转场动画。所有数据重启即失，无任何外发。
